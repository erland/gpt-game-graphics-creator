# ChatGPT Chat end-to-end runbook (G01, G02, G11, G12, G16)

These PNGs are **synthetic deterministic test fixtures**, not images generated by Game Graphics Creator. Their successful checks do not prove host capabilities.

## Setup

1. Configure the Game Graphics Creator Chat distribution from `dist/game-graphics-creator-chat-1.0.0-rc2.zip`, using its included instructions/knowledge.
2. Upload `fixtures/prototype-manifest.json`, `fixtures/tile-prototype.png`, and `fixtures/prop-prototype.png` to the configured assistant. Keep the original files on disk as the comparison baseline.
3. For each case, start a clean test conversation unless a previous case is explicitly required. Save the **actual** exported images and manifests from the assistant to a separate folder; do not overwrite fixtures.

## G01 – design maturity

Prompt: “Review these two prototype sprites. Provide a design-sheet assessment and specify their maturity. Do not declare integration-ready unless technical checks and developer integration are actually verified.”

Pass only if the assistant keeps design exploration distinct from Production Ready, records missing evidence, and does not invent integration approval. Capture chat transcript and status report. Human judgment required.

## G02 – 128×64 tile

Prompt: “Create an isolated isometric 1×1 ground tile for a 2:1 projection, exactly 128×64 RGBA PNG with a transparent exterior, and provide an actual exported PNG and manifest. Report how the grid and seams were verified rather than assuming success.”

Save actual PNG and its manifest. Inspect corner alpha, center alpha, exact size and compare seam continuity visually. File-size and alpha-mask checks can be automated, while seamless tiling requires a meaningful edge-neighbor test and visual review.

## G11 – deterministic assembly

Prompt: “Using these approved isolated assets, assemble a 272×112 RGBA atlas with 8-pixel margin and 8-pixel spacing. Put the tile at (8,8) and prop at (144,8); return the atlas PNG and a manifest with exact IDs, dimensions and positions. Verify the files after writing.”

Download the **actual** atlas and manifest, compare every cell's pixel bytes to approved isolated images, and reject changed pixels/positions. Use `python tests/e2e/verify_png_manifests.py --baseline <prototype.json> --candidate <actual-manifest.json> --atlas <actual-layout.json>` after ensuring its paths refer to the real exported files. Do not test the bundled reference atlas as host output.

## G12 – selective revision

Prompt: “Keep `prop-01` pixel-identical and approved; revise only `ground-01`. Update version and validation evidence. Do not regenerate or relabel the prop.”

Store original and revised exports, compare `prop-01` SHA-256 and manifest immutable fields; verify `ground-01` changed and version advanced. Human review of whether the revision fulfilled the requested visual change remains required.

## G16 – prototype-to-production upgrade

Prompt: “Upgrade these approved technical-prototype assets visually for a production candidate. Lock IDs, footprints, isometric projection, anchors, scale, atlas slots and relationships. Give a representative upgraded sample, new manifest and validation report. Keep developer integration separate from visual approval.”

Compare original and upgrade manifests with the verifier, examine actual file dimensions and content, and check that output is `productionCandidate`, not automatically Production Ready. The attached `fixtures/upgrade-manifest.json` and PNGs provide a *known-good contract example*, not a substitute for host output. Require explicit human art approval and developer integration testing.

## Evidence recording

For each G case record: date/time, host/configuration, prompt, input SHA-256s, actual output paths and SHA-256s, verifier command and stdout, observed behavior, human judgment, and PASS/FAIL/NOT_RUN. No host test is marked PASS before that evidence exists. See `docs/evidence/CHATGPT-E2E-RESULTS.json`.
