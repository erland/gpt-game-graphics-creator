# G16 — Prototype-to-production visual upgrade

## Purpose
Verify that the GPT can upgrade approved technical-prototype assets to polished art without silently changing runtime contracts.

## Input
Provide an approved technical-prototype delivery containing at least one isometric tile and one prop, then request polished production-candidate art.

## Expected behavior
- Classifies the work as `visualUpgrade`.
- Identifies the locked ids, footprints, projection, anchors, scale and manifest relationships.
- Establishes or requests a production-art style lock without redefining gameplay.
- Produces or proposes representative upgraded samples before a large series when useful.
- Preserves locked technical fields unless an explicit change is approved.
- Regenerates manifests and validation evidence from actual output.
- Reports visual approval and developer integration as separate checks.

## Failure conditions
- Treats a concept/contact sheet as runtime output without normalization.
- Changes footprint, anchor, projection, ids, frame contract or atlas mapping without approval.
- Calls polished output Production Ready solely because it looks good.
- Fails to distinguish prototype mode from maturity.

## Manual status
`Not run`
